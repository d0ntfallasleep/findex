# Базова версія lab-07

cProfile, весь корпус, індексація з позиціями та CLI-пошук «mars OR earth OR cylinder». Перед правками зафіксував три кандидати (власний час): tokenize — 23 мс під час побудови та 19 мс під час пошуку, pickle.dump — 23 мс, dataclasses.fields — 17 мс для 21 058 викликів при записі та читанні. Гіпотези: цикл видачі слів у Python викликає нативний regex; нативний pickle переходить у Python для кожного dataclass; метадані полів повторно обходяться в Python. Перший холодний запуск також витратив 227 мс на compile. Це час запуску CLI, тому окремо вимірюю прогрітий скорер.

## Перевірка гіпотез

У Scalene повторив операції побудови/запису та читання/пошуку 35 разів. Нижче відсоткові пункти всього профілю, підсумовані по рядках модуля; це атрибуція вибірок до місця виклику, а не точний таймер кожного C-виклику.

| Операція і модуль | Python | Native |
|---|---:|---:|
| Індексація, tokenize.py | 2,2 | 4,2 |
| Індексація, store.py | 0,0 | 1,0 |
| Пошук, dataclasses.py | 7,1 | 9,5 |

Токенізація та відновлення записів мають змішану ціну. Час збереження у store.py Scalene відніс здебільшого до нативної частини. Масиви прибрали виклики score на кожен постінг у прогрітому рейтингу. Boolean-фільтр та метадані для сумісності ще використовують звичайний індекс. Тому виграш скорера не дорівнює виграшу всього HTTP-запиту. py-spy працював у режимі --nonblocking, де окремі вибірки стека можуть бути пропущені.
